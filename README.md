# my planner

할 일을 입력하고, 마감을 확인하고, 완료로 넘기는 최소 일정 관리 템플릿.
Next.js(App Router) + Supabase.

## 실행

```bash
npm install
cp .env.example .env.local   # Supabase URL / publishable key 입력
npm run dev
```

## 화면 구성

한 화면에 네 가지 기능이 들어간다.

| 기능 | 위치 |
|---|---|
| Task 입력·수정·삭제 (모달) | `+ 일정 추가` 버튼 / 할 일 클릭 → `components/TaskModal.tsx` |
| 완료 처리 | 오른쪽 `할 일` 목록 체크박스 → `components/TaskList.tsx` |
| 다가오는 일정 / 지난 일정 (탭) | 오른쪽 위 카드 → `components/ScheduleCard.tsx` |
| 설정 (테마·알림·계정) | 사이드바 하단 톱니 → `components/SettingsModal.tsx` |
| 날짜별 회고 | 일정 보기 모달의 '회고' 칸 (마감일이 있을 때만) |
| 일정 보기 (→ 수정 버튼) | 일정 클릭 → `components/TaskDetail.tsx` |
| 특별 일정(형광펜) | 켜기: 목록 행 hover 시 ☆ / 모달 우측 상단 (`StarButton`) · 보이기: `.marker` |
| 아이콘 고르기 | 추가·수정 모달 제목칸 앞 이모지 클릭 → `components/EmojiPicker.tsx` |
| 분류 만들기·지우기·필터 | 사이드바 → `components/CategoryFilter.tsx` |
| 달력 (월간/주간) · 칸 눌러 추가 | 가운데 → `components/Calendar.tsx` + `MonthGrid` / `WeekGrid` |
| 마감일 고르기 | 추가·수정 모달 → `components/DatePicker.tsx` |
| 일정 검색 | 가운데 최상단 → `components/TaskSearch.tsx` |
| 프로필 사진 | 사이드바 상단 아바타 → `components/ProfileAvatar.tsx` |
| 플래너 이름 | 이름 옆 연필 → `components/PlannerName.tsx` |
| 테마 변경 | 설정 모달 → `components/ThemePicker.tsx` |
| 글꼴 변경 | 설정 모달 → `components/FontPicker.tsx` + `lib/fonts.ts` |
| PC 알림 | 설정 모달 → `components/NotifyToggle.tsx` + `lib/useNotifications.ts` |
| 카운터 · 배너 | 가운데 상단 → `CounterCard` / `BannerCard` |

레이아웃은 왼쪽 사이드바(고정) · 가운데 본문(스크롤) · 오른쪽 목록(고정)이다.

```
[사이드바]  [ 일정 검색                ]  [ 다가오는 일정 │ 지난 일정 ]
 프로필     [ D+ 카운터 ][ 배너 이미지 ]  [                          ]
 통계       [ 달력 (월간/주간)         ]  [ 할 일                    ]
 분류(+/-)  └ 날짜 칸을 누르면 그 날짜로 추가 모달이 열린다
 설정(톱니)
```

카운터와 배너는 비어 있어도 안내 문구가 자리를 지키므로, 아무것도 채우지 않은 상태에서도
화면이 깨지지 않는다. 둘 다 카드에 마우스를 올리면 편집·변경 버튼이 나온다.

오른쪽 컬럼(`app/page.tsx`)은 `max-h`로 화면 높이에 묶여 있고 **`overflow-hidden`이 함께
붙어 있어야 한다**. 이게 없으면 안쪽 목록이 `max-h`를 넘긴 만큼은 카드 안에서 잘려
보이지도 않는데 문서 스크롤 높이에는 그대로 더해진다. 할 일이 쌓이면 페이지 아래로
아무것도 없는 여백이 수백 px씩 생기고, 스크롤이 그 빈 곳까지 끌려간다.

## 개인화 (v1.1)

게스트는 `localStorage`(`my-planner:settings`), 로그인 상태는 서버 `settings` 테이블에
보관한다. 어느 쪽이든 `lib/store.ts`가 같은 모양으로 감싸므로 화면은 출처를 구분하지 않는다.
Task 데이터와는 완전히 분리돼 있고, 새로고침해도 유지된다.

### 테마

`app/globals.css`의 `:root[data-theme="..."]` 블록이 팔레트 전부다.
컴포넌트는 `canvas / card / line / ink / soft / accent` 같은 의미 이름만 쓰므로,
블록을 하나 더 추가하고 `THEMES` 배열에 항목을 넣으면 새 테마가 붙는다.
컴포넌트는 건드릴 필요가 없다.

색이 찍히는 자리(버튼, 월간/주간 토글 활성, 달력 오늘 표시, 형광펜)는
**예외 없이 `--accent`를 참조**한다. 값을 직접 적지 말 것 — 적는 순간 테마를 따라가지
않는다. 이전에 있던 별도 버튼 색(`--btn`)은 이 규칙에 어긋나서 없앴다.

팔레트는 전부 **파스텔**이다. `--accent`는 눈에 띄되 탁하지 않게, `--accent-deep`은
hover용으로 한 단계만 짙게, `--soft`/`--soft-deep`은 배경이라 그보다 훨씬 옅게 잡는다.
잉크 계열도 테마 색을 살짝 섞어서, 민트 테마의 글씨가 회색이 아니라 아주 옅은 초록빛을 띤다.

accent가 옅어진 만큼 형광펜(`.marker`)은 62%로 진하게 섞는다. 45%로는 파스텔 위에서
그은 자국이 보이지 않았다.

**`THEMES`의 `swatch`는 그 테마의 `--accent`와 같은 값이어야 한다.** 고칠 곳이 두
군데라 한쪽만 고치기 쉬운데, 어긋나면 설정 모달의 동그라미 색과 실제 화면 색이 달라진다.
눈으로는 '어? 좀 다른가?' 정도라 알아채기 어려워서 `lib/settings.test.ts`가 대신 본다.

`@theme inline`을 쓴 이유는 Tailwind 유틸리티가 색 값을 복사하지 않고 `var()`를
그대로 참조하게 하기 위해서다. 그래야 루트 변수만 바꿔도 즉시 반영된다.

**배경 그라데이션**(`--bg-gradient`)은 테마마다 따로 정의하고 `body` 한 곳에서만 칠한다.
지킬 것 세 가지:

- `background-color`가 아니라 `background`(또는 `background-image`)로 넣는다.
  그라데이션은 색이 아니라 이미지라서 `background-color`에 넣으면 조용히 무시된다.
- `background-attachment: fixed` — 스크롤해도 그라데이션이 늘어나지 않고 화면에 고정된다.
- 화면을 덮는 최상위 래퍼(`app/page.tsx`의 바깥 `div`)에 배경을 주지 않는다.
  단색 배경이 하나라도 있으면 body가 가려진다.

확인은 개발자 도구에서 `body`의 computed style에 `background-image: linear-gradient(...)`가
잡히는지 보면 된다. `none`이면 첫 번째나 세 번째, 잡히는데 안 보이면 두 번째 문제다.

배경 중간이 흰색이라 흰 카드가 묻히므로 카드에는 `shadow-card`(아주 옅은 그림자)를 준다.
카드류(달력, 할 일, 다가오는 일정, 카운터, 배너, 사이드바 통계)는 전부 흰 배경 +
보더로 통일한다. 반면 **카드 안쪽 항목은 보더도 그림자도 없이 여백(8px)만으로 구분**한다.
완료 항목도 같은 규칙이고 텍스트와 아이콘만 흐리게 + 취소선으로 처리한다.

새로고침 시 기본 핑크가 한 프레임 보이는 걸 막으려고, `lib/settings.ts`의
`THEME_BOOT_SCRIPT`를 `<head>`에 인라인으로 넣어 첫 페인트 전에 `data-theme`을 맞춘다.

### 글꼴

열여섯 가지 중에 고른다. 테마와 **똑같은 구조**다 — 설정에 값 하나를 저장하고, 화면은
`data-font`를 갈아끼운다. 컴포넌트는 글꼴 이름을 모르고 `--font-sans`만 쓴다.

```
:root[data-font="ridibatang"] { --app-font: "RIDIBatang"; }
--font-sans: var(--app-font), var(--font-noto-kr), "Malgun Gothic", ...
```

폴백을 뒤에 남겨두는 것이 중요하다. CDN이 늦거나 실패해도 글자는 보여야 한다.

#### 파일을 두지 않는 이유

한글 글꼴은 글자 수가 많아 하나에 0.3~1.3MB다. 열한 개를 저장소에 넣으면 배포 용량이
8MB 가까이 불어난다. 전부 눈누(noonnu.cc)에 올라온 CDN 주소를 그대로 쓴다.

**평소에는 고른 글꼴 하나만 내려받는다.** 브라우저는 실제로 쓰이는 `@font-face`만
가져가므로 나머지 열다섯 개는 건드리지도 않는다.

고르는 자리는 **드롭다운**이다. 열여섯 개를 죽 펼쳐두면 설정 모달을 글꼴 목록이 통째로
차지하고, 자주 바꾸는 값도 아니다. 접어둔 덕에 값이 하나 더 붙는다 — **목록을 펼칠
때만** 미리보기 때문에 전부 받아오고, 그것도 한 번뿐이라 그 뒤로는 캐시에서 온다.

목록에는 이름만 적는다. 어떤 글꼴인지는 그 글꼴로 그려진 이름이 이미 말해주고,
옆에 '동글동글한 손글씨' 같은 설명을 붙이면 줄이 복잡해지기만 한다.

미리보기에서 **글꼴 이름을 그 글꼴로 그리는 것**이 그 비용을 치르는 이유다. 이름만
나열하면 '리디바탕'이 어떻게 생겼는지 알 수 없어서 하나씩 눌러보게 된다.

#### 넣기 전에 확인할 것

**라이선스를 반드시 페이지에서 직접 확인한다.** '무료 글꼴'이라도 웹폰트(임베딩)만
따로 '조건부 허용'으로 막아둔 것이 흔하다. 실제로 **오이냉체와 세종글꽃체가 그래서
빠졌다** — 둘 다 인쇄·영상·BI는 자유롭지만 임베딩은 저작권자에게 먼저 물어야 한다.

지금 들어 있는 열여섯 개는 전부 **임베딩 허용 + 상업적 이용 가능**이고, 공통 금지
사항은 폰트 파일 자체를 파는 것뿐이다.

리디바탕은 라이선스에서 출처 표기를 권한다(의무는 아니다). 한 곳만 적으면 왜 저것만
적혀 있는지 이상해서, 글꼴 목록 맨 아래에 제공처를 전부 적는다(`FONT_CREDITS`).

주소는 넣기 전에 **실제로 200이 오는지 확인할 것.** 눈누 페이지를 요약해서 읽으면
주소가 틀리게 옮겨진다 — 페이지 HTML을 받아 `cdn.jsdelivr.net/...woff2?` 를 직접
뽑아내는 편이 확실하다. 나눔고딕은 눈누에 CDN이 없어서 fontsource(네이버 원본을
서브셋한 것)로 대신한다.

**파일 안의 이름도 확인해두면 좋다.** 카페24 아네모네에어 페이지가 내주는 파일의
내부 이름은 `Cafe24 Ohsquare air`다 — 눈누 쪽 연결이 어긋나 있을 수 있다.

굵기는 전부 normal 하나만 싣는다. 이 앱은 500(font-medium)까지만 쓰고 그건 브라우저가
만드는 가짜 굵기로 충분하다. 굵기마다 파일을 더 실으면 용량만 두 배가 된다.

도트 글꼴(Mona12)만 `locl`을 켜준다. 켜지 않으면 같은 코드포인트를 공유하는
중국어·일본어 자형이 섞여 나온다.

#### 글꼴마다 크기 맞추기

같은 13px이라도 글꼴에 따라 글자가 확연히 작아 보인다. 글꼴이 em 박스를 채우는 정도가
저마다 다르기 때문이다. `@font-face`의 **`size-adjust`** 로 맞춘다.

**눈대중으로 정하지 않았다.** 글꼴 파일을 전부 내려받아 `fontkit`으로 열고, 한글 대표
글자('한글일정가')의 잉크 높이를 재서 조선굴림체(0.9028)를 기준으로 계산했다.
잰 값은 생각보다 차이가 컸다 — 온글잎 박다현체는 0.6883이라 **131%**가 필요하다
(처음에 눈대중으로 118%를 줬는데 한참 모자랐다).

`fontkit`은 재는 데만 쓰고 의존성으로 남기지 않았다(`npm i --no-save`). 글꼴을
더할 때 다시 한 번 돌리면 된다.

화면 코드의 px 값을 건드리지 않고 그 글꼴일 때만 커지는 것이 핵심이다. 컴포넌트마다
글꼴을 따져 크기를 바꾸기 시작하면 걷잡을 수 없다. `font-size-adjust`(x-높이 비율)
대신 이걸 쓰는 이유는 '몇 %'로 바로 조절돼서 확인하기 쉬워서다.

**도트 글꼴(Mona12)에는 배율을 주지 않는다.** 픽셀 격자가 어긋나 글자가 뭉개진다.

#### 글꼴을 더할 때

고칠 곳이 **네 군데**다 — `lib/fonts.ts`의 배열, `globals.css`의 `@font-face`,
같은 파일의 `data-font` 규칙, 그리고 `settings_font_check` 제약. 하나만 빠뜨려도
조용히 어긋난다(CSS를 빠뜨리면 안 바뀌고, DB를 빠뜨리면 저장이 실패한다).
`lib/fonts.test.ts`가 네 군데를 대조한다.

### 프로필 사진 · 배너 이미지

둘 다 같은 업로드 경로(`lib/image.ts`)를 쓴다. jpg / png / webp, 5MB 이하만 받고,
webp data URL로 넣는다.

**자르지 않는다(v1.6).** 원본 비율 그대로 두고 긴 변만 줄인다 — 프로필 320px,
배너 960px. 예전에는 가운데를 잘라 256×256 / 960×384로 저장했는데, 그러면 잘려나간
부분이 영영 사라져서 나중에 '조금 위를 보여달라'고 할 방법이 없었다.

그래도 줄이기는 한다. 원본을 그대로 base64로 넣으면 5MB 파일이 약 6.7MB가 되어
localStorage 한도(보통 5MB)를 넘긴다.

#### 보일 위치 고르기

어디를 보여줄지는 `settings`의 `profile_pos_x/y`, `banner_pos_x/y`(0~100%)가 정하고,
화면은 `object-cover` + `object-position`으로 그린다. **원본이 그대로 남아 있으므로
몇 번을 다시 조정해도 화질이 깎이지 않는다.**

조작은 `components/ImagePositioner.tsx` 하나가 맡고 배너와 프로필이 같이 쓴다.
끌린 픽셀을 퍼센트로 바꿀 때는 `object-cover`가 그리는 크기를 그대로 다시 계산해서
**틀 밖으로 넘치는 양**을 구한다 — 그 넘치는 양이 곧 끌 수 있는 거리다.
넘치지 않는 축으로는 움직이지 않는다. 가로가 딱 맞는 사진을 좌우로 끌면 아무 일도
일어나지 않아야 하고, 억지로 움직이면 빈 여백이 드러난다.

`draggable={false}`가 필요하다. 브라우저 기본 이미지 끌기가 먼저 잡아채면 위치 조정이
아예 안 먹는다. 포인터는 `setPointerCapture`로 잡아둬서 틀 밖으로 나가도 끊기지 않는다.

프로필은 **64px 아바타에서 직접 끌지 않는다** — 너무 작아 원하는 위치를 잡을 수 없다.
팝오버에 132px 원으로 크게 펼쳐두고 거기서 끌게 하며, 결과는 위 아바타에 바로 비친다.

새 사진을 올리면 위치는 가운데로 되돌린다. 이전 사진의 위치를 물려받으면 엉뚱한 데가
보인다. 사진과 위치는 **한 번의 저장으로 함께** 넘긴다(`onSave({ image, x, y })`) —
나눠 저장하면 사진만 바뀌고 위치는 옛 값인 순간이 생긴다.

**이미 잘려 저장된 기존 사진**은 비율이 틀에 딱 맞아서 위치값 50이면 예전과 똑같이
보인다. 다만 옮길 여백이 없어서, 위치를 바꾸려면 다시 올려야 한다.

### 주간 뷰

가로 7일(일~토) 컬럼에 해당일 마감 Task를 카드로 세로 나열한다. 오늘 컬럼은 강조되고,
완료 Task는 월간과 같은 규칙(취소선 + 흐린 색)을 따른다.

참고 레퍼런스는 시간대 세로축이 있는 event 캘린더지만, 현재 `due_date`는 날짜 단위라
시간 정보가 없다. 그래서 **시간축 없이 날짜 컬럼 + 카드 목록** 형태로 만들었다.
`due_date`를 날짜+시간으로 넓힐 때 시간축을 함께 검토하면 된다.

주간 데이터는 따로 저장하지 않는다. 월간과 같은 `tasksByDate` 맵을 이번 주 날짜로만
읽는 파생 뷰다.

### 일정 보기 → 수정 (v1.4)

달력·할 일 목록·다가오는 일정·검색 **어디서 눌러도 `TaskDetail`(보기)이 먼저 뜬다.**
고치려면 거기서 '수정'을 한 번 더 눌러야 `TaskModal`이 열린다. 예전에는 곧장 수정
모달이 떠서, 내용만 확인하려고 눌렀다가 모르는 새 값을 건드릴 수 있었다.

보기 모달은 Task를 통째로 담지 않고 **id만 담는다**(`viewingId`). 사본을 담아두면
모달이 떠 있는 동안 별표를 켜도 옛 값 그대로라 화면이 따라 바뀌지 않는다. 목록에서
매번 찾아 쓰면 항상 최신이고, 그 일정이 지워지면 저절로 닫힌다.

별표와 삭제는 보기 화면에서 바로 할 수 있다. 별표는 고치는 내용이 아니라 표시라서고,
삭제는 수정 모달까지 들어갔다 나오는 게 번거로워서다. 삭제는 확인 창을 한 번 거친다.

두 버튼은 **삭제가 왼쪽, 별표가 오른쪽**이고 보기·수정 모달이 같은 순서를 쓴다.
자주 누르는 별표에 모서리에 가장 가까운 자리를 주고, 삭제는 한 칸 안쪽에 둔다.

삭제 버튼의 평소 색은 **별과 같은 톤**(`--ink-faint`)이다. 나란히 놓인 두 버튼의 색이
다르면 그것만으로 시선이 한쪽에 쏠린다. 위험 신호는 누른 뒤가 맡는다 — hover에서 빨강으로
바뀌고, 확인 창의 '삭제하기'는 그대로 빨강이다.

지울 때 `viewingId`도 비운다. 게스트는 id를 '최댓값 + 1'로 매기므로, 방금 지운 번호를
다음 일정이 그대로 물려받아 보기 모달이 혼자 열릴 수 있다.

### 할 일 추가·수정

새 모달을 따로 만들지 않고 `TaskModal`에 `task` prop을 넘겨 추가/수정을 겸한다
(`task`가 null이면 추가). 삭제는 모달 우측 상단의 휴지통 아이콘을 누르면 확인 모달(취소 / 삭제하기)이 뜬다.
Esc나 바깥 클릭은 확인 모달만 닫고 수정 모달은 남긴다.

#### 마감 시간 (v1.7)

`tasks.due_time`(time, nullable) 하나다. **날짜를 고른 뒤에만** 입력칸이 나오고,
날짜를 비우면 시간도 함께 버린다 — 날짜 없는 시간은 언제인지 알 수 없다. 같은 규칙을
DB(`tasks_due_time_needs_date_check`)와 `coerceTask` 양쪽에 걸어둔다.

`timestamptz`가 아니라 `time`인 이유: `due_date`가 이미 시간대 없는 `date`라서,
한쪽만 시간대를 갖게 하면 자정 부근에서 두 값이 서로 다른 날을 가리킨다.
개인 플래너라 '내 시계로 몇 시'면 충분하다.

표시는 `formatTime`이 만든다. `toLocaleTimeString`을 쓰지 않는 이유는 브라우저·OS
로캘을 타서 같은 값이 기기마다 다르게 보이기 때문이다. 어차피 'HH:MM' 문자열이라
직접 만드는 편이 짧고 확실하다.

정렬은 **같은 날짜 안에서 시간이 이른 것부터**, 시간을 안 정한 건 그날의 맨 뒤로 보낸다
('몇 시까지'가 있는 일을 먼저 보는 게 자연스럽다). 이 규칙은 `byDueThenCreated` 한 곳에
있고 `byDueAsc`/`byDueDesc`가 그걸 다시 쓴다.

#### 마감일 — 직접 만든 달력으로 고른다

네이티브 `<input type="date">`를 **쓰지 않는다**(`components/DatePicker.tsx`).

네이티브 선택기는 달을 넘기는 것만으로도 `change`가 올라와서, 고르지도 않은 날짜가
값으로 들어갔다. 직접 그린 달력에서는 **칸을 누른 것만 값이 된다** — 달을 아무리
넘겨도 아무 일도 일어나지 않는다.

구성은 위에서부터 `오늘 / 내일 / 모레` 바로가기, `‹ 2026년 9월 ›` 달 이동, 요일 머리,
날짜 격자다. 오늘은 테두리로, 고른 날짜는 채움으로 구분한다 — 채우기를 둘 다 쓰면
어느 쪽이 고른 건지 알 수 없다.

**여러 날짜는 누른 만큼 쌓이고, 이미 고른 날짜를 다시 누르면 빠진다.** 그래서 예전에
있던 `날짜 더 추가` 버튼이 필요 없어졌다.

**수정할 때도 날짜를 더 고를 수 있다(v1.7).** 이 일정은 첫 날짜로 옮겨가고, 나머지
날짜에는 같은 내용의 일정이 새로 만들어진다. '수정'과 '추가'를 한 번에 처리하는 곳은
`page.tsx`의 `submitTask` 한 군데다 — 저장 버튼도 `저장 + N개 추가`로 바뀌어,
무엇이 일어날지 누르기 전에 보인다.

요일 순서는 본문 달력(`MonthGrid`)과 똑같이 **일요일부터**다. 참고한 시안은 월요일
시작이지만, 한 앱에서 주 시작이 두 가지면 날짜를 셀 때마다 헷갈린다.

달력에서 고른 칸이 있으면 추가 모달이 **그 날짜가 골라진 채로** 열린다(`initialDate`).
고른 칸이 없으면 아무것도 안 고른 채로 연다 — 마감일은 선택 항목이지 기본값이 아니다.
한때 오늘로 미리 채워봤지만, 오늘이 아닌 날을 잡을 때 지우는 손이 한 번 더 들어가서
되돌렸다.

### 달력 칸을 눌러 바로 추가

월간·주간 모두 **칸을 누르면 그 날짜로 추가 모달이 곧장 열린다**(노션 달력과 같은 동작).

한때는 '칸을 눌러 날짜를 고른 뒤 + 일정 추가를 누르는' 두 단계였다. 고른 표시를 링으로
그리고 선택을 해제하는 규칙까지 있었는데, 결국 같은 일을 두 번 눌러서 하는 것이었다.
지금은 한 번이면 되고 링도 선택 상태도 없다. 대신 칸에 마우스를 올리면 오른쪽 위에
흐린 `+`가 떠서 누를 수 있다는 걸 알린다.

헤더의 `+ 일정 추가`는 날짜 없이 연다. 날짜가 붙는 건 달력 칸을 눌렀을 때뿐이다.

칸 안에 일정 버튼이 들어가므로 칸을 `<button>`으로 감쌀 수 없다(버튼 중첩). `div` +
`role="button"`으로 두고, 안쪽 일정 버튼은 `stopPropagation`으로 추가 모달이 함께
열리지 않게 막는다. 칸의 `+` 표시는 `pointer-events-none`이다 — 클릭은 칸이 받아야 한다.

### PC 알림

마감 시간을 정해둔 일정이 그 시각이 되면 브라우저 알림을 띄운다.

**이 탭이 열려 있는 동안에만 온다.** 브라우저를 닫아도 오게 하려면 서비스 워커와 푸시
서버가 필요한데 이 앱이 짊어질 무게가 아니다. 화면에도 그 한계를 그대로 적어둔다.

켜짐/꺼짐은 `settings`가 아니라 **localStorage**에 둔다(`my-planner:notify`). 알림 권한
자체가 브라우저·기기마다 따로 붙는 것이라, 회사 PC에서 켠 게 휴대폰에서도 켜지면 곤란하다.
그래서 이것만은 계정이 아니라 기기를 따라간다.

지킬 것 셋:

- 권한 요청은 **사용자가 스위치를 누른 그 자리에서** 해야 브라우저가 창을 띄워준다.
  화면이 뜨자마자 요청하면 조용히 거절된다.
- 이미 지난 시각은 알리지 않는다. 지금 켠 순간 옛 알림이 우르르 쏟아지면 곤란하다.
- 예약은 **앞으로 24시간 안**만 한다. `setTimeout`은 약 24.8일이 넘으면 즉시 터지는
  버그가 있고, 먼 일정까지 타이머로 들고 있을 이유도 없다.

알림에는 **필터를 거치지 않은 전체 할 일**을 넘긴다. 지금 '운동'만 보고 있다고 해서
'업무' 마감 알림을 놓치면 안 된다.

### 날짜별 회고

`reflections` 테이블 한 벌이고 **날짜가 곧 열쇠**다(사용자당 하루 한 건).
`(user_id, date)`에 유일 제약을 걸어 upsert 한 번으로 새로 쓰기와 고쳐 쓰기를 모두 처리한다.

**들어가는 길은 일정 보기 모달 하나뿐이다.** 일정을 열면 `일정 / 회고` 두 칸이 있고,
회고 쪽은 그 일정의 **마감일 하루치만** 다룬다. 이미 쓴 날은 칸 이름에 `✓`가 붙어서
눌러보기 전에 알 수 있다.

마감일이 없는 일정에는 회고 칸이 아예 안 나온다. '어느 날의 회고'인지 정할 수 없고,
억지로 오늘에 붙이면 엉뚱한 날에 글이 쌓인다.

할 일의 `memo`로 만들 수도 있었지만 그러면 하루를 통으로 돌아보는 자리가 없어지고
메모와 역할이 겹친다. 할 일은 '앞으로 할 것', 회고는 '지나고 나서 적는 것'이다.

**빈 회고는 없는 것과 같다.** 내용을 비우고 저장하면 행을 지우고, 읽을 때도
`coerceReflection`이 걸러낸다. 그래야 '있는데 비어 있는 회고'라는 어중간한 상태가 없다.

저장은 자동이 아니라 버튼이다. 타이핑하는 동안 계속 서버로 보내면 느리고 어디까지
저장됐는지도 알 수 없다. 대신 저장이 **끝난 뒤에** 화면을 바꾼다(할 일의 낙관적 갱신과
반대다) — 한 번 누르는 것이라 기다림이 짧고, '저장됨' 표시가 정확해야 한다.

### 설정 모달

테마·알림·계정은 저마다 성격이 다르지만 **자주 건드리지 않는다**는 점이 같다. 사이드바에
늘 펼쳐두면 매일 보는 화면(할 일·분류)을 밀어내기만 해서, 톱니 하나로 접어 넣었다.

계정 칸에서 비밀번호를 바꾼다(`supabase.auth.updateUser`). 지금 세션으로 바로 고치므로
**옛 비밀번호는 묻지 않는다** — 세션이 이미 본인 확인이다. 두 번 입력해 맞는지 보고,
`PASSWORD_MIN`은 로그인 화면과 같은 값을 쓴다.

모달을 열 때마다 비밀번호 칸은 접고 비운다. 입력해둔 게 남아 있으면 안 된다.

게스트에게는 계정 칸 대신 로그인 안내가 나온다. 사이드바 아래에도 '로그인'을 한 번 더
두는데, 설정 안에만 있으면 처음 온 사람이 찾지 못한다.

메모는 `tasks.memo` 한 컬럼이고 모달의 textarea 하나가 전부다. 공백만 남기면 `null`로
저장한다 — 빈 문자열이 섞이면 '메모 없음' 판정이 두 갈래가 된다. 목록에서는 줄이 길어지지
않도록 펼치지 않고, 할 일 위에 마우스를 올리면 제목 아래에 툴팁으로 붙는다.

할 일 목록에서는 **체크박스와 이름 영역의 클릭 범위가 분리**돼 있다. 체크박스는 완료
토글, 이름 영역은 수정 모달이다. 완료된 할 일도 똑같이 수정할 수 있고, 완료 상태는
모달에서 바꾸지 않는다(체크박스 역할).

완료 목록은 최근 `DONE_LIMIT`(10)개까지만 그린다. 다 쌓아두면 남은 할 일이 아래로
밀려나기만 한다. 지운 게 아니라 접어둔 것뿐이라 전체 개수는 라벨에 `완료 30 · 최근 10개`
형태로 남겨둔다.

## 분류 · 별표 · 자동 아이콘

### 사용자가 만드는 한 단계 분류 (v1.5)

v1.3~1.4에는 `일 → 업무·회의·프로젝트 / 일상 → 약속·운동·개인`이라는 **코드에 박힌
2단계 목록**이 있었다. 쓰지도 않는 하위 항목이 화면만 차지해서 한 단계로 줄이고,
이름도 사용자가 정하게 했다. **지금 코드에 박힌 분류는 하나도 없다.**

`categories` 테이블 한 벌이고, `tasks.category_id`가 거길 가리킨다. 만들기와 지우기는
**왼쪽 사이드바**에서 한다(통계 카드 아래). 고르는 자리와 관리하는 자리를 같이 둔 이유는
분류가 몇 개 안 되고, 따로 설정 화면을 만드는 것보다 찾기 쉬워서다.

**분류를 지워도 거기 달려 있던 할 일은 남는다** — 미분류로 돌아갈 뿐이다. 서버에서는
`on delete set null`이 해주지만, **게스트(localStorage)는 직접 해줘야 한다**
(`guestStore.removeCategory`). 안 하면 없는 분류를 가리키는 할 일이 남아 어느 필터에도
안 걸려서 화면에서 사라진 것처럼 보인다.

지우기는 휴지통을 한 번 누르면 '지우기 / 취소'로 바뀌고, 한 번 더 눌러야 실제로 지워진다.
모달까지 띄우지 않는 건 사이드바에서 자주 하는 작은 조작이라서다.

같은 이름은 만들 수 없다(`categories_name_unique`). 둘이면 사이드바에서 어느 쪽을
누른 건지 알 수 없다. 이름 검사는 `validateName` 한 곳에 있고 화면과 저장소가 같이 쓴다.

필터는 **`app/page.tsx`의 `visible` 한 곳에서만 적용한다**. 달력·다가오는 일정·지난
일정·할 일·사이드바 통계가 전부 이 배열에서 파생되므로 화면 어디를 봐도 기준이 같다.
목록마다 따로 걸면 한 군데를 빠뜨렸을 때 달력과 목록이 서로 다른 걸 보여준다.

저장된 필터가 **이미 지워진 분류를 가리킬 수 있다**(다른 탭에서 지웠거나 게스트 데이터가
어긋났거나). 목록에 없는 id면 전체 보기로 떨어뜨린다 — 안 그러면 아무것도 안 보이는
화면에서 빠져나올 방법이 없다.

**검색만 예외로 필터를 거치지 않은 전체 `tasks`를 받는다.** 찾는 일정이 지금 필터
밖에 있다는 이유로 검색에 안 나오면 그게 더 헷갈린다.

분류를 정하지 않은 할 일은 '미분류'로 남고 **전체 보기에서만** 보인다. 억지로 어느 쪽에
넣지 않는다. 기본 분류를 자동으로 만들어주지도 않는다 — 사용자가 지울 수 있는 것을
앱이 되살리면 그게 더 이상하다.

게스트가 로그인하면 **분류는 서버로 옮기지 않는다**. 로컬 id가 서버 id와 아무 관계가
없어서 짝을 맞출 수 없다. 옮겨온 할 일은 미분류로 시작한다.

### 특별 일정 (별표)

`is_starred` boolean 하나다. 켜면 할 일·다가오는 일정·지난 일정에서 **맨 위로 올라가고**,
어디서든 **제목에 형광펜이 그어진다**(`globals.css`의 `.marker`).

**별은 켜고 끄는 자리에만 있다.** 한때 제목 앞에 ★을 붙였는데, 이미 일정마다 이모지가
있어서 11px 글자 옆에 기호가 둘씩 늘어서면 무엇이 무엇인지 알아보기 어려웠다. 형광펜은
자리를 전혀 차지하지 않으면서 한눈에 띈다. 행 배경으로 들어올리던 것도 같이 없앴다 —
표시가 두 가지면 어느 쪽이 진짜 규칙인지 헷갈린다.

`.marker`에서 지킬 것 두 가지.

- **글자 아래쪽(62%)만 덮는다.** 전체를 채우면 형광펜이 아니라 그냥 배경색이 된다.
- **`box-decoration-break: clone`** — 없으면 줄이 넘어갈 때 첫 줄에만 칠해진다.
  주간 뷰는 제목이 세 줄까지 간다.

완료된 일정에는 긋지 않는다. 이미 흐리고 취소선이 있어서 형광펜까지 겹치면 탁해진다.

정렬은 각 비교 함수에 조건을 심지 않고 `starredFirst(cmp)` 래퍼로 씌운다. 목록마다
정렬 기준이 다르지만(마감 오름차순 / 내림차순) '별표가 먼저'는 공통이라 한 곳에만 둔다.

목록의 ☆ 버튼은 꺼져 있을 때 `display`가 아니라 `opacity`로 숨긴다. 자리를 늘 차지하게
둬야 hover할 때마다 버튼이 생겨 옆 글자가 밀리는 일이 없다.

추가·수정 모달에서는 **오른쪽 위 별 아이콘 하나가 전부다**(v1.5). 예전에는 '특별 일정으로
표시' 라벨이 붙은 체크 줄을 아래쪽에 뒀는데, 켜짐/꺼짐이 별 모양으로 이미 읽히는데도
줄 하나를 통째로 쓰고 있었다. 라벨이 없는 만큼 별은 크게 그린다.

`StarButton`은 **버튼 크기와 별 크기를 따로 받는다**(`className` / `iconClassName`).
둘이 늘 같은 비율은 아니어서다 — 목록에서는 누르기 편하게 영역만 넓히고, 모달에서는
별 자체를 키운다.

### 아이콘 — 이모지 (v1.4)

v1.3까지는 인라인 SVG를 직접 그렸다. 도형 다섯 개일 때는 괜찮았지만 '회의·운동·생일'
같은 뜻을 담으려니 손으로 패스를 그리는 방식이 한계였다 — 아령이 화살표처럼 보이고
케이크가 뭉개졌다. 그래서 **이모지 문자를 그대로 저장하고 그대로 그린다**.

그 대가로 **색은 포기했다.** 이모지는 CSS로 tint할 수 없다. 어차피 이모지가 색과 뜻을
다 가지고 있어 색상 선택은 중복이었으므로 모달에서 항목을 뺐다. `tasks.icon_color`
컬럼은 지우지 않고 남겨뒀다 — 되돌리기 쉽게.

이모지는 본문 폰트(조선굴림체)에 글리프가 없다. 지정하지 않으면 브라우저가 알아서 대체
폰트를 골라 크기와 세로 정렬이 OS마다 흔들리므로, `globals.css`의 `.emoji` 클래스에서
폰트 스택을 못 박는다. `TaskIcon`은 `w-[1.25em]` 고정 폭을 주는데, 이게 없으면 이모지마다
글리프 폭이 달라 목록의 제목 시작점이 줄마다 어긋난다.

### 아이콘 자동 매칭 — 시작값이지 잠금이 아니다

아이콘은 **기본적으로 자동**이다. 저장할 때 제목과 분류 이름을 보고 `lib/autoIcon.ts`가
정한다. 화면 어디에서도 제목을 보고 아이콘을 정하지 않는다 — 규칙은 그 파일에만 있다.

다만 자동이 늘 맞을 수는 없어서 **직접 고를 수도 있다**. 제목 입력칸 앞의 이모지를
누르면 선택기가 열린다(`components/EmojiPicker.tsx`).

고른 값(`pickedIcon`)이 null이면 자동이다. 잠그지 않고 '자동'으로 되돌리는 버튼을 함께
둔 이유는, 한 번 고르면 영영 자동이 안 되는 것보다 오갈 수 있는 편이 낫기 때문이다.

#### 이모지 선택기

OS 이모지 판(Win + .)과 같은 꼴이다. 화면은 위에서부터 **검색 / 분류 / 격자 / 직접 넣기**
네 칸이고 **칸마다 선으로 끊어 둔다** — 한 덩어리로 붙여놨더니 어디까지가 검색이고
어디부터가 목록인지 알아보기 어려웠다.

분류 탭은 글자가 아니라 **아이콘**이다. 글자로 두면 일곱 개가 한 줄에 안 들어가 가로
스크롤바가 생기는데, 그 막대가 화면에서 가장 눈에 띄는 것이 돼버렸다. 고르지 않은 탭은
흐리게 두고(일곱 개가 똑같이 진하면 어느 게 켜졌는지 안 보인다), 고른 분류의 이름은
격자 위에 글자로 적어 무엇을 보고 있는지 분명히 한다.

**외부 패키지를 쓰지 않는다.** 이모지 라이브러리는 대부분 수천 개 항목과 영어 키워드를
함께 싣고 오는데, 정작 '생일'로 검색하면 아무것도 안 나온다. 목록 238개를
`lib/emojiData.ts`에 직접 들고 있고 **검색어가 한국어**다. 새 이모지를 넣을 때
`k`에 적을 것은 이름이 아니라 **쓰임새**다 — 🏥는 '십자'가 아니라 '병원 진료 치과 검진'.

검색 중에는 분류 탭을 감춘다. 검색은 분류를 가로질러 찾으므로 탭이 무의미하다.

Esc는 `capture` 단계에서 잡아 `stopPropagation`한다. 모달도 window에서 Esc를 듣고
있어서, 그냥 두면 선택기를 닫으려다 모달까지 함께 닫힌다.

238개로 세상 모든 이모지를 덮을 수는 없어서 맨 아래 **직접 넣는 칸**을 둔다. 넣은 값은
`firstGrapheme`으로 **맨 앞 한 글자만** 남긴다 — 문장을 통째로 붙여넣는 일이 잦고,
`slice(0,1)`로 자르면 👨‍👩‍👧 같은 건 조각나서 깨진다.

우선순위는 **① 제목 키워드 → ② 분류 이름 → ③ 📌**이다. 분류는 사용자가 지은 이름이라
미리 짝지어둘 수 없는데, '운동'·'공부'처럼 키워드 표에 이미 있는 말을 쓰는 경우가 많아서
**이름 자체를 같은 표에 통과시키는 것만으로 꽤 맞는다.**

`RULES` 배열은 **위에서부터 먼저 걸리는 것이 이긴다 — 순서가 규칙의 일부다.** '회의'가
'점심'보다 위에 있어서 "점심 회의"는 🍔가 아니라 💬가 된다. 반대로 가장 넓은 말인
'약속·예약'은 맨 아래에 둔다. 한 글자짜리 키워드는 넣지 않는다(`약` 하나를 넣으면
약속·예약·계약이 전부 걸린다).

제목을 타이핑하는 동안 입력칸 앞 이모지가 실시간으로 바뀐다 — 무엇이 저장될지 먼저 보인다.

### 옛 아이콘 이름 호환

v1.3까지 저장된 `'circle'`·`'star'` 같은 값은 `lib/icons.tsx`의 `LEGACY_ICONS`가 읽을 때
이모지로 옮긴다. 서버 데이터는 0006 마이그레이션이 한 번에 정리하지만, **게스트
localStorage에는 마이그레이션을 걸 곳이 없어서** 읽는 쪽이 계속 감당해야 한다.

## 데이터

저장하는 엔티티는 `tasks` 한 벌뿐이다. 달력과 일정 목록은 별도 테이블이 아니라
같은 데이터를 마감일 기준으로 다르게 보여주는 파생 뷰다.

| 필드 | 타입 | 비고 |
|---|---|---|
| `id` | bigint identity | 시스템 자동 부여, 화면 비노출 |
| `title` | text | 필수. 공백만 있으면 DB check 제약으로 거부 |
| `due_date` | date | 선택. 없으면 D-day 목록·달력에 나오지 않음 |
| `is_done` | boolean | 기본값 false |
| `created_at` | timestamptz | 자동 기록 |
| `icon` | text | 이모지 문자(1~8자). 기본은 자동, 직접 고를 수도 있다. null이면 📌 |
| `icon_color` | text | **v1.4부터 화면에서 쓰지 않는다.** 예전 데이터 보존용 |
| `due_time` | time | 선택. `due_date`가 null이면 이것도 null |
| `memo` | text | 선택. 500자 제한. 공백만 남으면 null로 저장 |
| `category_id` | bigint | `categories`를 가리킨다. null이면 미분류. 분류를 지우면 null이 된다 |
| `is_starred` | boolean | 기본값 false. 특별 일정 표시 |

분류는 별도 테이블이다.

| `categories` | 타입 | 비고 |
|---|---|---|
| `id` | bigint identity | |
| `user_id` | uuid | 기본값 `auth.uid()` |
| `name` | text | 1~12자. 사용자당 유일 |
| `sort_order` | int | 사이드바 순서. 만든 순서를 쓴다 |

`icon` / `icon_color` / `memo` / `category_id`는 nullable, `is_starred`는 default라
이 컬럼들이 생기기 전에 저장된 할 일도 그대로 읽힌다.

**게스트(localStorage) 데이터는 읽는 지점에서 반드시 `coerceTask`를 거친다.** 예전에
저장된 항목에는 새 필드가 아예 없어서, `is_starred`가 `undefined`인 채로 흘러가면 별표
정렬이 조용히 어긋난다. DB에는 제약을 걸 수 있지만 localStorage에는 걸 곳이 없으므로
`readLocalTasks`가 그 역할을 한다.

모달에서 색을 고르지 않으면 저장 시점의 `--accent` 값을 굳혀서 넣는다. 반대로
`icon_color`가 null인 할 일은 `fill="var(--accent)"`로 그려서 테마를 바꾸면 함께 바뀐다.
완료된 할 일은 아이콘도 `--ink-faint` 톤으로 흐려진다.

스키마는 `supabase/migrations/0001_create_tasks.sql`부터 번호순으로 쌓인다.
`icon`/`icon_color`(0002), `user_id`와 `settings`(0003), `memo`(0004),
`area`/`category`/`is_starred`와 테마 4종(0005), 이모지 아이콘(0006),
사용자 정의 분류(0007), 사진 위치(0008), 마감 시간(0009), 회고(0010), 글꼴(0011),
글꼴 하나 제거(0012), 글꼴 여섯 종 추가(0013)가 뒤에 붙었다.

0012처럼 **목록을 좁히는** 마이그레이션은 순서가 중요하다. 제약을 좁히기 전에 그 값을
쓰고 있는 행을 먼저 되돌려야 한다 — 안 그러면 기존 행이 새 제약을 위반해서 ALTER
자체가 실패한다.
새 테마를 넣을 때는 `settings_theme_check`도 함께 넓혀야 한다 — 목록이 코드와 DB
양쪽에 있다.
새로 추가하는 컬럼은 전부 nullable이나 default로 둔다 — 그래야 기존 행을 건드리지 않고
배포할 수 있다.

0005는 `settings_theme_check`를, 0006은 `tasks_icon_check`를 **갈아끼운다**. 테마를 더할
때는 목록이 코드와 DB 양쪽에 있다는 걸 잊지 말 것. 아이콘 쪽은 0006에서 값을 열거하는
제약을 버리고 길이 제한(`tasks_icon_len_check`, 1~8자)만 남겼다 — 이모지는 종류를 미리
다 적을 수 없다.

0006은 기존 행의 `'circle'` 같은 값을 이모지로 바꾸는 `UPDATE`도 함께 돈다. 앱이 읽을 때도
옮겨주므로(`LEGACY_ICONS`) 이 마이그레이션이 늦어도 화면은 깨지지 않는다.

**0007은 컬럼을 지우는 첫 마이그레이션이다.** `tasks.area`/`tasks.category`와
`settings.filter_area`/`filter_category`가 사라진다. 그냥 버리지 않고, `area`를 쓰던
사용자에게는 '일'·'일상' 분류를 만들어 그 할 일들을 새 분류에 다시 걸어준다.
하위 카테고리(업무·회의…)는 사라진다 — 한 단계로 줄이기로 한 이상 옮겨 담을 자리가 없다.

### 계산해서 쓰는 값 (저장하지 않음)

- **D-day** — `due_date − 오늘`을 매번 계산 (`lib/date.ts`의 `getDday`).
  당일은 `오늘`, 남았으면 `D-2`, 마감이 지났으면 `2일 지남`이다. 지난 쪽만 표기 방향이
  다른 건 '지난 일정' 탭에서 `D+2`보다 한눈에 읽히기 때문이다.
- **다가오는 일정** — `is_done = false` AND `due_date`가 있고 AND `D-0 ~ D-10`.
  별표 먼저, 그다음 마감일 오름차순.
- **지난 일정** — `is_done = false` AND `due_date`가 있고 AND 마감이 지난 것.
  별표 먼저, 그다음 최근에 지난 순. **완료한 과거 일정은 넣지 않는다** — 시간이 갈수록
  목록만 길어지고 정작 처리해야 할 것이 그 안에 묻힌다. 체크하면 목록에서 빠진다.
- 두 탭은 한 카드를 나눠 쓰고, 카드 높이는 `50vh`로 묶여 있으며 넘치면 안에서만 스크롤한다.
  **탭은 오직 사용자가 누를 때만 바뀐다.** 한때 '놓친 일정이 0건이면 다가오는 일정으로
  돌아간다'는 효과를 넣었다가, 그게 탭을 아예 못 누르게 만들었다 — 지난 일정이 없을 때
  탭을 누르면 상태가 바뀌자마자 되돌려져서 눌러도 반응이 없는 것처럼 보였다.
  비어 있으면 비었다고 보여주면 될 일이지 탭을 막을 일이 아니다.
- **달력 배치** — `due_date`가 있는 Task를 해당 날짜 칸에 표시.

날짜는 전부 `'YYYY-MM-DD'` 문자열로 다룬다. `Date` 객체로 왕복시키면 UTC 파싱 때문에
하루가 밀릴 수 있어서, 일수 계산은 `Date.UTC` 기준으로만 뺀다.

## 검색

제목으로만 찾고, 달력이나 목록을 걸러내지 않는 **조회용**이다. 검색을 껐다 켜도 화면
상태가 흐트러지지 않는다. 일/일상 필터도 거치지 않는다(위 '분류' 절 참고).

**Enter가 안 먹던 문제의 원인은 IME였다.** 한글을 조합하는 동안 Enter는 '조합을 확정한다'는
뜻이고 그 확정 키가 `keydown`으로도 올라온다. 가드가 없으면 '치과'를 치고 Enter를 누른
순간 조합 확정용 Enter가 곧바로 첫 결과를 열어버린다. 그래서 핸들러 맨 앞에서
`e.nativeEvent.isComposing`이면 아무것도 하지 않는다. 방향키도 조합 중에는 IME가 후보를
고르는 데 쓰므로 함께 막는다.

↑/↓로 결과를 옮기고 Enter로 열며 Esc로 닫는다. 마우스를 올린 항목이 곧 방향키가 가리키는
항목이 되게 맞췄다 — 둘이 따로 놀면 강조가 두 군데 생겨 어느 쪽이 열릴지 알 수 없다.

## 자간

`body`의 `letter-spacing: -0.02em` **한 곳이 전부다.**

예전에는 월간 달력만 자간을 벌리고 주간만 죄어놨다. 조선굴림체 하나만 쓰던 때는 그게
맞았지만, 글꼴을 열 가지 중에 고르게 되면서 글꼴마다 맞는 자간이 달라져 그 예외가
의미를 잃었다. 지금은 컴포넌트에 `tracking-` 을 흩뿌리지 않는다 — 여기만 고치면
전체가 따라온다.

`.emoji`만 `letter-spacing: normal`로 되돌린다. 이모지에 자간을 주면 뒤따르는
글자와 사이가 뜬다.

## 테스트

`npm test` — `vitest`로 `lib/`의 순수 로직만 본다. 화면은 `npm run dev`로 직접 확인한다.

담아둔 것은 이모지 자동 매칭(순서 우선순위 포함), 옛 아이콘 이름 호환(`toIcon`),
분류 이름 검사·필터·정규화, D-day 라벨, `coerceTask`다.
눈으로 훑어서는 틀린 걸 알아채기 어렵고, **틀려도 화면이 깨지지 않고 조용히 잘못된 값을
보여주는** 것들이라 골랐다. `autoIcon.test.ts`의 '위쪽 규칙이 이긴다' 테스트는 `RULES`
배열 순서를 바꾸면 깨진다 — 깨졌다면 새 순서가 의도한 것인지 다시 따져봐야 한다.

## 보안 메모

v1.2에서 로그인을 붙이면서 `tasks`·`settings`의 RLS 정책은 모두 소유권 기준
(`auth.uid() = user_id`)으로 좁혔고 `anon` 권한은 회수했다. 게스트는 서버를 아예 쓰지 않고
localStorage에만 쓴다.

`update` 정책에는 `USING`과 `WITH CHECK`가 **둘 다** 걸려 있어야 한다. `WITH CHECK`가
없으면 소유자를 남에게 넘길 수 있다.

### Settings

사이드바 순서는 프로필 사진 → 이름 + 연필 → 통계 카드 → 테마다.
프로필 사진은 사진이 없으면 클릭 시 곧장 파일 선택으로 가고, 있으면 팝오버로
`다른 사진 업로드 / 사진 삭제`를 고르게 한다(바깥 클릭·Esc로 닫힘).
이름은 연필을 눌러 인라인 편집하며 Enter·바깥 클릭이 저장, Esc가 취소,
빈 값은 기본값 `my planner`로 되돌아간다.

배너 카드는 높이 180px 고정에 `object-fit: cover`라, 세로로 길거나 납작한 이미지를
올려도 레이아웃이 밀리지 않는다. placeholder 상태와 이미지 상태의 높이가 같다.
사진 위에 마우스를 올리면 `위치 조정 / 변경 / 삭제`가 나온다.

| 필드 | 값 | 기본값 |
|---|---|---|
| `planner_name` | 문자 (20자) | `my planner` |
| `profile_image` | data URL (webp), 긴 변 320px | `null` |
| `profile_pos_x` · `profile_pos_y` | 0~100 (%) | `50` (가운데) |
| `banner_pos_x` · `banner_pos_y` | 0~100 (%) | `50` (가운데) |
| `theme` | 9종 (아래) | `pink` |
| `font` | 16종 (`lib/fonts.ts`) | `joseon` (조선굴림체) |
| `calendar_view` | `month` / `week` | `month` |
| `banner_image` | data URL (webp), 긴 변 960px | `null` |
| `counter_date` | `'YYYY-MM-DD'` | `null` |
| `counter_label` | 문자 (20자) | `시작한 날` |
| `filter_category_id` | `categories.id` | `null` (전체) |

테마는 `pink` / `lavender` / `mint` / `cream` / `gray`에 v1.3에서
`blue` / `sage` / `coral` / `mocha`가 더해져 9종이다. **새 테마를 넣을 때 고칠 곳은 네 군데다** —
`globals.css` 블록(그라데이션 포함), `settings.ts`의 `THEMES`, `settings_theme_check` 제약,
그리고 `lib/icons.tsx`의 색 거리표. 마지막 걸 빼먹으면 모달 팔레트에 같은 색 동그라미가
두 번 나온다(실제로 `blue` 테마는 '블루' 프리셋과 거리가 0이라 자동으로 걸러진다).

사이드바 스와치는 `flex-wrap`이다. 안쪽 폭이 164px이라 20px 스와치는 한 줄에 다섯 개까지만
들어간다 — `justify-between`으로 늘려두면 테마를 더할 때 조용히 삐져나간다.

필터를 `calendar_view`와 같은 자리에 둔 이유는 성격이 같은 '보기 상태'이기 때문이다.
덕분에 게스트(localStorage)와 로그인(서버) 양쪽 저장 경로를 새로 만들지 않아도 됐다.

읽을 때 형식을 검사해서(`coerce`) 손상된 값이나 손으로 고친 값이 들어와도 기본값으로
떨어지게 했다. 저장이 실패하면(용량 초과 등) 화면 상태도 되돌려서 표시와 저장 내용이
어긋나지 않는다.

## 범위 밖

관리자 페이지. 확장 후보로 남긴 것: 분류 이름 바꾸기·순서 바꾸기, 분류별 색,
완료 시각(`completed_at`), 반복 일정, 주간 뷰의 시간축.

**회고를 모아 보는 화면**은 두지 않는다. 한때 오른쪽 카드에 탭으로 넣었다가 걷어냈고,
지금은 일정 보기 모달에서만 들어간다 — 회고는 그날 일정을 보다가 적는 것이지,
목록을 훑으러 오는 것이 아니다.

**탭을 닫아도 오는 알림**도 여기 있다. 서비스 워커와 푸시 서버(VAPID 키, 구독 저장,
발송 스케줄러)가 필요해서 지금 구조로는 감당이 안 된다. 지금은 탭이 열려 있는 동안만
온다.

여전히 제외: 크롭·회전 편집 UI, 여러 장 관리, 이미지 서버 업로드,
다크 모드, 커스텀 컬러 피커, 폰트 변경, 할 일별 색상(v1.4에서 이모지로 대체).

다크 모드는 카드·그림자·그라데이션이 전부 밝은 배경을 전제로 맞춰져 있어서, 넣으려면
`--canvas`/`--card`/`--ink` 계열과 `shadow-card`를 전부 다시 잡아야 한다. 테마 프리셋을
하나 더 추가하는 것과는 작업량이 다르다.

여러 탭을 동시에 열어도 서로의 변경은 실시간으로 반영되지 않는다(새로고침 필요).
Realtime 구독은 넣지 않았다.
